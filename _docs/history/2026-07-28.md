## Section 1 — mask output profile (`--mask-profile {full-audit,public}`)

### 목적

[확인] v2 constrained 파이프라인은 프레임마다 진단용 M0~M4 5장을 **항상 영구 저장**한다. 공개/학습용 데이터셋에는 amodal(M0)과 visible(M4) 2장만 있으면 되고, 나머지 3장은 렌더 비용 + 디스크 + "이게 무슨 마스크냐" 혼란만 남긴다. 기존 500-record 진단 동작은 그대로 두고, 출력 정책만 프로파일로 분기한다.

판단 지표(완료 기준)
- `full-audit`(기본): 기존 500-record 동작과 완전 하위호환 (M0~M4 전부 저장, f_static/f_cargo/f_context/f_explicit exact)
- `public`: 이미지당 영구 mask **정확히 2장**, M1/M2/M3 파일 0개
- `public`에서 per-source 분수는 **`None`(null)** — 0.0 아님, 저해상도 근사 아님
- `f_total`은 public에서도 **exact** (M0/M4만으로 계산 가능)
- visible ⊆ amodal 픽셀 포함관계 검증

### M1~M3를 "렌더하지 않는" 것이 실제로 되는가 — 실측

[확인] 2프레임 public 스모크(`--mask-profile public --render-profile dataset-quality --n 20 --start 0 --count 2`, seed 7500) Blender 로그의 `Saved:` 줄이 프레임당 3개(rgb + mask_amodal + mask_visible)뿐이다. 렌더 후 삭제가 아니라 홀드아웃 패스 자체가 2회만 돈다.

```text
프로파일        프레임당 Saved 줄   mask 파일   생성된 디렉토리
────────────────────────────────────────────────────────────────
public          3 (rgb+2)          2          mask_amodal/, mask_visible/   (mask/ 없음)
full-audit      6 (rgb+5)          5          mask/
```

같은 seed(7500) 2프레임을 두 프로파일로 각각 렌더한 결과 mask 면적이 완전히 일치(f0000 14304, f0001 80813) — 프로파일은 **어떤 마스크를 남기는가만** 바꾸고 씬/기하는 건드리지 않는다.

### compatibility lookup 제공 방식

`mask_profiles.resolve_frame_mask_path(root, idx, stage)` 하나로 통일했다. 프로파일 순서대로 후보 경로를 만들어 **실제 존재하는 파일을 우선 반환**하고, 없으면 `detect_profile(root)` 결과의 경로를, 그것도 아니면 레거시 `mask/fNNNN_<name>.png`를 돌려준다. 따라서 기존 로더는 호출부 1행만 바꾸면 두 레이아웃을 모두 읽는다(audit_pnp_eligibility, overlay_v2_detailed에 적용). **public 출력에 `m0`/`m4` 같은 암호 파일명을 중복 저장하지 않는다**(지시 준수 — public 셋에는 `mask/` 디렉토리 자체가 생기지 않음).

### 지시와 다르게 처리한 부분

1. **`mask_area_amodal`을 public뿐 아니라 full-audit label에도 넣었다.** 지시는 public 스키마로만 명시했지만, 두 프로파일을 한 로더로 읽으려면 amodal 면적 필드 이름이 같아야 한다. full-audit에서는 `mask_area_target_only`와 값이 동일한 추가 필드이므로 기존 필드/값 정의를 바꾸지 않는 순수 additive 변경이다.
2. **`records.jsonl`의 record 스키마에는 아무 키도 추가하지 않았다.** `tests/test_usable_completion_mode.py::test_records_mode_record_schema_is_unchanged`가 146키 정확 일치를 요구하는 frozen snapshot이라, `mask_profile`을 record에 넣으면 기존 테스트를 고쳐야 한다. 프로파일 출처는 label / `driver_summary.json` / `records.jsonl`의 `mask_paths` 값으로 확인 가능하므로 record는 건드리지 않았다.
3. **`--mask-names` 기본값을 문자열에서 `None`으로 바꿨다**(audit). 프로파일에서 stage를 유도하되 사용자가 명시하면 그대로 쓰기 위해서다. 명시 호출(`--mask-names m0,m1,m2,m3,m4`)의 동작은 종전과 동일.
4. **`collect_duplicate_filenames`에는 public mask 디렉토리를 넣지 않았다.** `mask_amodal/fNNNN.png`와 `mask_visible/fNNNN.png`는 basename이 같은 게 **설계**라, 포함하면 전 프레임이 duplicate로 오탐된다(해당 판정은 원래 rgb/label 이름만 본다). 코드에 이유를 주석으로 남겼다.
5. **`v2_realize`의 홀드아웃 hide 목록을 리팩터링했다.** 지시엔 없지만, "public은 2패스만 돈다"를 bpy 없이 검증하려면 stage→hide-group 매핑이 테스트 가능한 자리에 있어야 했다. 매핑 값은 리팩터 전 호출과 1:1 동일하며 이를 검증하는 테스트(`test_hidden_object_sets_match_the_pre_refactor_holdout_calls`)를 추가했다.
6. **소형 Blender 스모크를 2프레임 × 2프로파일 실행했다**(지시상 선택 사항). 렌더 루프를 실제로 바꿨기 때문에 bpy-free 테스트만으로는 "M1~M3를 정말 안 그린다"를 증명할 수 없어서다. 출력은 스크래치패드에 두었고 `data/pallet/` 아래에는 아무것도 만들지 않았다.

### 지시와 다르게 처리한 부분

1. **복사한 블록의 인라인 색 리터럴을 이름 있는 상수로 올렸다**(`COLOR_X_EDGE = (255, 80, 80)` 등).
   값은 archive와 1바이트도 다르지 않고, 테스트가 상수 자체를 exact match로 고정할 수 있게 하려는 목적이다.
2. **그리기 본체를 4개 내부 함수로 쪼갰다.** 라벨에 투영이 없을 때 `pts2d[a]`가 IndexError로 죽는 대신
   패널만이라도 남기려면 분기가 필요한데, 복사한 라인의 들여쓰기를 바꾸지 않으려고 함수로 뺐다.
   함수 안의 코드는 원본 그대로다.
3. **`drw.text(..., font=FONT)`를 명시했다** (원본은 font 인자 없음). Pillow 10.1부터 `load_default()`가
   anti-aliased TrueType을 돌려주도록 바뀌어서, "font 인자 없음"을 그대로 두면 Pillow 12에서 패널 글꼴이
   통째로 달라진다(실측: 순수 흰색 픽셀 0개, 글자 크기·자간 상이). `load_default_imagefont()`로 archive가
   쓰던 6x11 비트맵 폰트를 명시적으로 요청해 **원본 모양을 유지**한다.
4. **missing 값 처리를 위해 포맷 문자열에 단위를 넣었다**(`"{:.2f}m"`). 값이 있을 때 출력 문자열은 archive와
   동일하고, 없을 때만 `Distance: N/A`처럼 단위 없이 나온다(`Distance: N/Am` 방지).
5. **elevation은 어댑터에서 1자리, cam height는 2자리로 반올림**해서 넘긴다. archive는 meta_extra에 이미
   반올림된 값을 넣어 두고 패널에서는 원시 출력을 했으므로(`Elev: 32.5deg`), 같은 화면을 만들려면
   반올림 위치가 어댑터여야 한다. `Cam dist(surf)`는 archive처럼 반올림하지 않았다.
6. **과거 보고서(`reports/v2_revision/quality_smoke50/summary.md`)의 overlay 경로는 고치지 않았다.**
   그 문서는 어제 실제로 만든 산출물(`eda_phase6/overlay_detailed/`)의 기록이라 사실 그대로 두는 게 맞다.
   기본 경로 변경은 앞으로 생성되는 것에 적용된다.
