## 1. ★visible_kp_count 정정 (라벨 정확성)

사용자 지적: "어떻게 9개가 다 보인다는거지? 자체가림이 있어서 9개는 절대 다 보일 수 없는데.

**둘 다 맞았다.**  `run_v2_scene_logic._visible_keypoint_metrics` 는

```
uv9 = 8코너 + centroid                     <- 중앙점을 셌다
visible = in_frame AND (occ 미측정 OR occ<0.5)  <- 자체가림은 측정조차 안 함
```

`occlusion_fraction` 은 **외부 물체**에 의한 가림만 재고, 팔레트 자신의 뒷면 코너는
"미측정(None)" 이라 **보이는 것으로 처리**됐다.

수정: centroid 제외 + 자체가림 반영.  실측 30장에서 최대 9 -> 6 (상한 7 이내).

## 2. 자체가림 계산 — `SP2.self_visible_corner_mask`

볼록 육면체에서 코너는 **인접 3면 중 하나라도 전면이면** 보인다.  한 시점에서 전면은
1~3개뿐이라 보이는 코너는 **4 / 6 / 7 개**다 — 8개는 기하학적으로 불가능하다.

★**코너 순서에 의존하지 않게 만들었다.**  이 파이프라인에는 canonical 순서
(`blender_math.canonical_corners_yup`: 0=FTR 1=FTL 2=FBL 3=FBR 4=RTR 5=RTL 6=RBL 7=RBR)와
**v4 순열**(`perm_v4`, 예: [1,5,6,2,0,4,7,3]) 두 가지가 함께 돈다.  면을 인덱스로
박아두면 한쪽에서 반드시 틀리므로, **한 코너의 최근접 3점 = 세 모서리 방향**이라는
성질로 축을 기하에서 유도한다(면대각·체대각은 항상 모서리보다 길다).
순열을 넣어도 결과가 같음을 테스트로 고정.

## 3. ★G1 근본 수정 — 같은 버그가 탐색기에도 있었다

`SP2.external_corner_gate_metrics` 의 G1 은 **이미 "코너 4개 이상"을 요구**하고 있었다.


이라 실제보다 코너를 많게 셌다.  그래서 **탐색기는 "G1 통과"라 판단하고 렌더까지 했는데
라벨에서는 4점 미만**이 나왔다 — 거부율 74%의 주원인.

`self_visible=` 인자를 추가해 in_frame 과 교집합을 잡는다(인자를 안 주면 기존 동작 유지).

**왜 이게 최선인가** — 검토했다가 버린 대안들:

```

앙각을 40° 이상으로     ✗ 사용자가 원하는 저앙각 정면 뷰를 없앤다
center side 신설       새 개념 + 기존 판정과 상호작용 위험
                       (G1.5 에서 순서 변경이 context 를 전멸시킨 전례)
★ G1 계산 정정          제약이 이미 있다.  계산만 고치면 탐색기가
                       "코너를 살리는 배치"를 스스로 찾는다
```

★**사용자가 지적한 두 상황이 자동으로 처리된다**:
- **0° 정면 뷰**: 자체가림으로 앞면 4코너만 보임 -> V_vis=4 -> G1 통과 (평면 PnP 로 풀림)

  거의 항상 miss -> 매 프레임 재계산 -> 매 프레임 누적.

수정: `pallet_geometry.authored_scale(obj)` — .blend 원본 scale 을 **최초 1회만**
캡처해 고정.  첫 호출이 `_select_and_place_pallet` 의 `obj.scale` 쓰기보다 앞이고,
프로세스 재시작 시 .blend 를 다시 읽으므로 청크 분할 실행에서도 같은 값이다.

★**기존 1만 장·300장은 영향 없다** — 균등 배율만 쓰던 구간이라 자기교정이 작동했다.

## 4. Q3 — 거리 분포.  "10m 최다"는 그림 읽기의 함정이었지만 요구는 타당했다

Figure 1(b)는 **결합밀도**다.  10m 근처가 밝은 건 프레임이 많아서가 아니라 그 거리에서
화면크기가 좁은 범위(0.05~0.1)에 뭉쳐 단위면적당 밀도가 높기 때문이다.  실제 최다는
**1.5~2m (21.0%)** 였고, 9~10m 에 두 번째 봉우리(12.7%)가 있는 **쌍봉**이었다.

### ★ratio 가중치만으로는 못 고친다 — 두 가지 이유

1. `PROJ_SIZE_FRAC` **quota 가 구간 점유율을 강제**한다.  거리 선호 가중치를 걸어도
   실현이 정확히 0.200×5 로 나왔다(20,000회 실측).
2. ratio->거리 변환이 **fx 에 의존**한다.  fx 를 70% 랜덤(300~700)으로 돌리므로:

```
ratio 구간    fx=300       fx=450       fx=615       fx=700
0.20~0.40    1.5~2.6 m    1.9~3.9 m    2.6~5.3 m    3.0~6.0 m
0.60~1.00    - 불가        - 불가        1.5~1.8 m    1.5~2.0 m
```
   bin 4 는 고fx 에서 통째로 1.5~2.0m 라 구간 내부를 어떻게 뽑아도 못 뺀다.

### 구현 — 규약 변경 + fx 조건부 선호

- `DIST_PREF_MEDIAN_M = 3.5`, `DIST_PREF_LOG_SIGMA = 0.75` (로그정규 목표).
- `proj_size_bin_distance_spans(fx, W)` — **그 프레임의 intrinsics 로** 각 ratio 구간이
  덮는 거리 구간을 계산.
- `distance_pref_weights(spans)` — 목표 분포가 그 구간에 싣는 질량.
- `_deficit_pick(..., weight=)` — quota deficit 에 곱하는 **soft steer**.  실현 가능한
  구간은 1e-9 하한을 남겨 deficit 이 살아 있게 하고, 전 구간이 quota 를 채운
  fallback 도 균등이 아니라 선호 가중으로 뽑는다(대량 생성 후반부가 전부 이 경로).
- 구간 **내부**도 목표 분포 역변환으로 샘플링.  ratio-uniform 이면 거리 쪽이 1/d^2 로
  쏠려 근거리에 다시 쌓인다.  `_lognorm_cdf/_lognorm_icdf/_erfinv`(Winitzki + Newton
  3회, 왕복오차 1e-15) 신설.
- ★`PROJ_SIZE_FRAC` `[0.20]*5` -> **`[0.18, 0.25, 0.40, 0.15, 0.02]`**.
  실제 sample_frame 20,000회로 목표 히스토그램에 맞춰 격자 탐색한 값이다.

### 규약을 깬 것에 대한 기록

원래 균등 0.20 은 "기하 등비 구간 × 균등 = 거리 log-uniform = scale-invariant
커버리지"라는 **의도된 규약**이었다(v2 규약 Phase C).  이걸 배치 거리대 집중과
맞바꿨다.  **대가: 화면크기 ">60%"(초근접) 구간 20% -> 2%.**  초근접은 사용자가
1만 장 감사에서 직접 "너무 가까이 있는 건 문제"라고 지적한 구간이고, 2% 면 1만 장에서
200장이라 케이스 자체는 남는다.  ★평가셋 실측이 나오면 ELEV_BIN_FRAC 과 함께 재조정.

## 7. 내가 틀렸다가 정정한 것 (2부)

1. **"비균등 스케일 = 형상 왜곡이라 불가"** -> 재보지 않고 단정.  ±15% = 2.1px.
