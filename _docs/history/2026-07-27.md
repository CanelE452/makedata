### Phase 2 — 지면 연속성 감사 (ground continuity)

**목적**: Phase 1의 10m 거리 상한 이후에도, 유한한 procedural floor plane(50m×50m quad)의 경계가 화면에
노출되거나 카메라–팔레트 사이 지면이 끊기는 프레임이 남는지 프레임 단위로 감지·기록한다. 판단 지표는
(1) 신규 지표가 record/label에 실제로 노출되는가, (2) 20프레임 이상 실측 통과, (3) 실패가 실측되지 않으면
floor 크기를 그대로 유지.

**변경 파일**

- `scene_placement_v2.py` (bpy-free)
  - `GROUND_PROBE_COUNT = 11`, `GROUND_PROBE_STEP_TOLERANCE_M = 0.05`
  - `ground_probe_points_xy(camera_xy, target_xy, count=11)` — 카메라 지면투영점↔팔레트 centroid XY를
    양 끝 포함 균등 분할
  - `procedural_plane_bounds(center_xy, plane_size)`, `plane_bounds_margin_m(point_xy, bounds)`
  - `_ground_probe_kind(sample, floor_object_name)` — floor / support / other / steep / miss 분류
  - `ground_continuity_verdict(samples, ...)` — 5개 계약 지표 + 진단 필드 집계
- `scene_visibility_v2.py` (bpy)
  - `check_ground_continuity(...)` — 기존 `support_surface_at_xy()`를 11회 재사용(신규 raycast 유틸을 만들지
    않음). `_temporary_hidden()`으로 pallet/cargo/context/explicit occluder를 한 번만 숨기고 프로브 →
    각 ray가 "그 위에 올라간 물체"가 아니라 지면 자체를 보게 한다. support 없음 → `pass=None`
    (`reason="no_support_objects"`), 조용한 통과 금지.
- `v2_realize.py`
  - `_measure_ground_continuity(rs, centroid_world)` 신규. floor plane 중심은 실제 `FloorRandPlane`
    오브젝트 위치(anchor `procedural_support_shift` 반영분)를 쓴다.
  - `measure()`에서 holdout mask 렌더 **이전**(씬이 최종 렌더 가시성인 시점)에 호출, 결과를 meas에 `**ground`로 병합.
  - `label()`의 `v2_labels`에 8개 필드 배선.
- `run_v2_scene_logic.py` — `_record_rendered()`에 동일 지표 배선.
- `audit_v2_scene_logic.py` — 7개 CSV 컬럼 + `ground_continuity_summary(rows)`(N-frame pass율/실패 index/
  최소 edge margin/reason 카운트) + `failures`에 `ground_continuity_fail`/`procedural_floor_edge_risk`.
  구 데이터셋(값 None)은 소급 실패시키지 않도록 명시적 False만 실패로 센다. `fatal_failure_reasons`는 미변경.

**통과 조건과 임계값 근거**

- 각 probe가 support 역할 surface에 적중(miss/비-support/steep-normal = 실패).
- 인접 probe 간 support z 단차 ≤ 0.05m. 근거: KS T-11 팔레트 높이 150mm의 1/3이자 기존 support contact
  tolerance(20mm)의 2배 이상 — 접촉 노이즈와 procedural plane의 6mm 오프셋은 통과, 팔레트 스케일에서
  눈에 보이는 턱은 실패.
- plane 경계 밖 probe가 하나라도 있으면 `procedural_floor_edge_risk=True`(+ 연속형 `procedural_floor_edge_margin_m`).

## Phase 3 — 최종 RGB 기준 품질 측정 + noise tier + render profile 분리

### 문제 (Phase 0에서 [확인])

디스크에 남는 최종 RGB는 post-effect(vignette 최대 −35%, gaussian noise, JPEG 재압축)를 거친 이미지인데,
G5 게이트와 라벨의 luma는 그 **이전**(raw) 값이었다. 실행 순서가

### 지시와 다르게 처리한 부분

- **`render_post()`가 항상 dict를 반환하지는 않는다.** `tier=None`(레거시 드라이버 호출)일 때는 기존처럼
  float `noise_scale`을 반환한다. `_g5_reverify.py:102-104`가 반환값으로 산술 비교(`abs(noise_scale - 공식)`)를
  하므로 무조건 dict로 바꾸면 "레거시 드라이버 3개는 건드리지 않는다" 조건을 깬다. tier를 주는 v2 경로에서만
  dict를 반환한다.
- **`measure()` wrapper는 "post-effect 이전에 부르면 final == raw"** 라는 의미가 된다. 레거시 드라이버
  (`_v2_pilot_2k.py` / `_b3_asset_check.py` / `_g5_reverify.py` / `_v2_calib_200.py`)는 모두 `measure()` →
  `render_post()` 순서이고 `luma_frame`/`luma_pallet`(= raw 별칭)만 읽으므로 동작·수치가 완전히 동일하다.
  docstring에 이 제약과 "신규 코드는 3단계로 나눠 호출하라"를 명시했다.
- `label()`의 `luma_actual`/`luma_pallet_actual`을 final로 바꾸지 않고 **raw 의미로 유지**했다. 이 두 필드는
  `analyze_v2_scene_logic.py`의 LUMA 커버리지 감사가 소비 중이라 의미를 조용히 바꾸면 기존 EDA 해석이
  무효가 된다. Phase 8 continuous EDA는 새 `luma_frame_final`을 쓰면 된다.
- record의 `noise_scale` 필드는 제거하고 `dark_factor`(0~1)와 실제 적용 `gaussian_sigma`로 대체했다.
  tier 체계에서 전역 배율 개념이 더는 의미가 없기 때문.

### 지시와 다르게 처리한 부분 (중요)

**PnP의 3D 점을 `pnp_solver.make_pallet_keypoints_3d()`(고정 canonical object frame)로 쓰지 않았다.**
지시문에는 "2D-3D 순서 일치 확인됨"이라고 돼 있었으나 실제 라벨로 검증하니 틀렸다:

- v2 라벨의 `keypoint_convention`은 `camera_dynamic_0123_v4`이고 `perm_v4`가 프레임마다 다르다
  (`v2_realize.label():3884-3892`). 즉 인덱스 0이 가리키는 물리 코너가 프레임마다 바뀐다.
- 실측: 프레임별 `dimensions_m`으로 canonical 9점을 만들어 라벨 `pose_transform`+K로 투영하면
  `projected_cuboid`와 **최대 426px** 어긋난다(f0000 401.8 / f0003 426.5 / f0004 11.7px). 중심점만 0.
  canonical 점으로 PnP를 풀면 exact-GT reprojection이 최대 **153.5px**까지 나온다
  (`canonical3d_exact_reproj_mean_px` 컬럼으로 전 프레임 기록해 뒀다). [확인]
- 대신 라벨 자신의 `cuboid`(world 8점, `projected_cuboid`와 **같은 perm으로 기록됨**)를 centroid 기준으로
  옮긴 점집합(X_obj = X_world - centroid_world)을 3D 점으로 썼다. 검증: 이 대응으로 K·view matrix를
  통해 재투영한 값과 라벨 `projected_cuboid`의 최대 오차가 435프레임 전체에서 **6.3e-13 px**,
  PnP로 복원한 translation이 라벨 `location`과 **정확히 일치**한다. [확인]
- centroid 기준으로 옮긴 이유: `PalletPnPSolver.solve()`의 `t[2]<0 → R=-R` 플립(`pnp_solver.py:154-156`)이
  물체 중심 좌표계를 전제로 하기 때문. world 원점 그대로 쓰면 카메라 뒤의 world 원점에서 이 플립이 발동해

### 문제 (Phase 0에서 [확인])

`audit_v2_scene_logic.py`의 mask 검사는 `mask_area()`가 돌려주는 **스칼라 면적 5개의 단조성**

`scene_placement_v2.validate_mask_decomposition`도 스칼라 5개 입력이다.

### 변경 파일 / 함수 (`scripts/data_prep/blender/audit_v2_scene_logic.py`)

기존 `mask_area()`는 **손대지 않고** 그대로 뒀다(Phase 4 `audit_pnp_eligibility.py`가 이 함수를

- `strict_decode_mask(path)` — `Image.verify()`(구조/CRC) + `convert("L").load()` 2단계 strict

  `content_sha256`(전경 packbits 해시) / `width` / `height` / `all_black`.
  모듈 최상단에 `ImageFile.LOAD_TRUNCATED_IMAGES = False` 고정(다른 import가 전역으로 True로
  바꿔놓으면 잘린 PNG가 조용히 0으로 채워진다).

### 실측이 설계를 바꾼 지점 3가지 (전부 435프레임 실행 결과가 근거)

1. **all-black mask는 바이트 해시로 절대 안 묶인다.** empty-target 4프레임(48/321/453/478) 중
   321·453·478은 **같은 960×540 all-black인데 sha256이 전부 다르다**. Cycles가 임계값(>127) 아래
   안티에일리어싱 noise를 남기기 때문. → all-black은 바이트가 아니라 **content 기준(`__all_black__`
   키)**으로 묶도록 바꿨다. 이걸 안 했으면 지시문이 요구한 "서로 다른 frame의 all-black M0
   duplicate = empty-target defect"가 **한 건도 안 잡혔다**. [확인]
2. **바이트 해시만으로는 "같은 mask"를 못 센다.** f0000의 m0/m1은 area가 31029로 동일한데 sha256이
   다르다(같은 이유). → `content_sha256`(shape + `np.packbits(fg)`의 sha256)를 추가하고 duplicate
   그룹핑의 기본 키로 썼다. 바이트 일치는 `byte_identical` 플래그로 **구분해서** 보고한다
   (byte-exact = stale 파일 복사 의심 / content-only = 같은 실루엣 재렌더 = 정상 no-op).
   435프레임에서 within-frame content 그룹 617개 중 byte-exact는 3개뿐이었다. [확인]
3. **"occluder를 놨는데 stage mask가 같다" != 결함.** 최초 규칙(배치 카운터만 보고 판정)으로
   돌렸더니 `unexpected_identical_stage` 4건(f212/269/325/469, 전부 context-rich)이 떴는데, 전부
   **context prop이 팔레트를 안 가린 정상 케이스**(`n_context_placed>0` & `f_context==0.0`)였다.
   → 상태를 4값(`absent` / `placed_no_occlusion` / `contradiction` / `unknown`)으로 쪼개고,
   **record가 f_X>0을 주장하는데 mask가 동일한 경우만** `unexpected_identical_stage`(결함)로
   좁혔다. 재실행 후 이 클래스 0건. [확인]

### 설계에서 실제로 결정적이었던 지점

1. **absent / null / present(0) 3상태 분리.** 구 데이터셋에는 Phase 1~3 필드가 아예 없다.
   `rec.get(k)`로 읽으면 "필드 없음"과 "값이 0"이 똑같이 falsy가 되어 조용히 0으로 보인다.
   → `pick()`은 **키 존재 여부**로 present를 판정하고, 텍스트를 `N/A (field absent)` /
   `N/A (null)` / 실제 값 3가지로 분리한다. 실데이터에서 `bbox min side: 0.0 px`(f0229,
   V_vis=0), `ground fails: 0`처럼 **진짜 0이 N/A로 뭉개지지 않는 것**을 확인했다. [확인]
2. **감사 CSV를 Phase 2 필드의 소스로 쓰면 안 된다.** `eda_phase5/audit_frames.csv`에는
   `ground_continuity_pass` 컬럼이 있지만 값이 비어 있다(record에서 복사하므로). 이걸 소스에
   포함하면 "이 렌더는 Phase 2 이전이라 필드가 없다"가 `N/A (null)`로 잘못 표시된다.
   → Phase 2 필드는 record/label만 본다. Phase 5(mask inclusion·hull)는 감사 CSV가 **직접 계산한**
   값이므로 그대로 쓴다.
3. **Phase 4 CSV의 `camera_distance_used_m`은 "기록된 거리"가 아니다.** 구 데이터에서는
   `camera_distance_source=label_recomputed`다. 이걸 `dist actual (rec)`에 넣으면 Phase 1 필드가
   있는 것처럼 보인다. → record 전용 행(`dist actual/target/limit (rec)`)과 라벨 기하 유래 행
   (`dist centroid` / `dist surface`)을 **분리**하고, violation 행에 출처를
   `[record]` / `[derived, limit 10m fb]`로 명시한다.
4. **`pose_transform`은 object→CAMERA다** (object→world 아님). 실측: 그 translation을 K로 투영하면
   `projected_cuboid_centroid`와 **정확히** 일치, `build_view_matrix(location, look)`+K는
   `projected_cuboid`를 1e-14 px로 재현. 따라서 pose axis는 world 변환 없이
   `K @ (R_pose[:,i]*0.5m + t_pose)`로 그린다. [확인]
5. **1px 컨투어는 안 보인다.** M0는 3px 두께(dilate), M4는 1px로 위에 올려 occluder가 먹은 부분이
   cyan 후광으로 드러나게 했다(f0033: M0 0.950 / M4 0.767 hull IoU와 시각 일치).
6. **텍스트는 열 폭으로 하드 클립.** 첫 시도에서 `ok [label-derived (no Phase1 field)] (fallback 10m)`가

## Phase 8 — 논문용 continuous EDA + falsy-0 회귀 수정

### 문제 (Phase 0 baseline에서 [확인], 이번에 수정)

`analyze_v2_scene_logic.py` 곳곳에 `r.get(key) or fallback` 패턴이 있어 **정수 0 / Boolean False가
missing과 같은 버킷에 들어갔다**. Python에서 `0 or "(missing)"` → `"(missing)"`, `False or ...` → 동일.
Fig.16/17/18뿐 아니라 `azimuth_bin` / `V_actual` / `V_vis` / `v_target` / `cross_tab_plot` /
`scatter_plot(color_key)` / `stage` / `reject_reason` 전부 같은 결함이었다.

동시에 기존 EDA는 **연속 제어변수를 전부 bin bar로만** 본다. 논문에 쓰려면 bin 경계 선택에
의존하지 않는 서술(ECDF / KDE / kernel-smoothed pass curve)이 필요하다. 단, 본질적으로 이산인 변수를
연속처럼 위장하면 안 되므로 그 구분을 **코드로 강제**한다.

### 지시와 다르게 처리한 것

1. **`analyze_v2_scene_logic.py`의 `x or fallback`을 전부 없애지는 않았다** — `len(rows) or 1`,
   `stage_total[st] or 1`은 0-division 가드라 0→1이 의도된 동작이다. 그대로 뒀다.
2. **8.1의 fx / exposure / runtime을 13 figure 안에 넣지 않고 14/15/16으로 분리**했다.
   필수 13개 목록에 이들이 없어 번호를 밀지 않기 위해서다.
3. **`projected_size_actual`을 [0,1]로 무음 클립하지 않았다** — 지시는 "[0,10] 밖 밀도 안 그림"인데
   여기서 문제는 측정 자체의 과대읽기다. ECDF는 전량 유지 / 밀도·fit만 제한 / 제외 개수와 최대값을
   캡션·JSON에 기록하는 방식으로 처리했다.
4. **감사 manifest 출처 검사를 추가**했다(지시에 없음). 넣지 않으면 다른 데이터셋 분석에 435행이
   섞이는 것을 실제로 재현했기 때문이다.
