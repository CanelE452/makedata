### 목적

### 마스크 방식 결정 — 2-pass holdout (★중요)
Blender 5.1.1 EEVEE(Next)에서 마스크 PoC를 MCP로 직접 검증한 결과:
- **Object Index pass(IndexOB) 미지원**: `view_layer.use_pass_object_index=True`로 켜도 RLayers 출력에 `Image, Alpha`만. IndexOB 없음.
- **compositor API 전면 변경**: `scene.node_tree` 없음 → `scene.compositing_node_group`(NodeTree). `CompositorNodeComposite`/`OutputFile.file_slots`/`base_path` 등 노드·속성 대거 변경 → compositor 역설계 비효율.
- **채택 = 2-pass holdout**: 메인 렌더 후, 팔레트만 흰 emission / 나머지 메시 전부 검정 emission / world=None / view_transform=Standard 로 1패스 더 렌더 → 이진 visible mask. occluder·cargo가 검정으로 가린 부분이 자동 제외됨. PoC `data/pallet/_mask_poc/holdout_mask.png`로 팔레트 흰 실루엣·구멍 검정 제외 확인.

## 카메라 기준 0123 라벨 적용 (compute_perm_v4 이식) + 메시 정리 시도

### 0123 — object-frame 고정 → camera-facing 동적 (해결)
- 문제: palletobj `gen_palletobj_scenarios.py:reorder()`가 object-frame 고정 순서라 카메라 뷰에 따라 0123이 안 돌았음(v4는 camera-facing).
- 해결: `blender_math.py:138 compute_perm_v4`(카메라를 가장 마주보는 side 면=FRONT={0,1,2,3}, normal-facing 기준) 이식.
  - `gen_palletobj_scenarios.py` 수정 3곳: ① `import numpy as np; from blender_math import compute_perm_v4` ② render_frame에서 `reorder(corners_w)` → `compute_perm_v4(corners_np, uv8_np, cam_pos)`로 perm 계산 후 `kps_world=[corners_w[perm[k]]]` ③ keypoint_convention `"y_up_8corners_plus_centroid"` → `"camera_dynamic_0123_v4"`.
  - blender_math.py는 numpy만 의존(다른 모듈 import 없음) → CLI import 안전.
- 검증(seed 777 재생성, _mask_test10 덮어씀): 10/10 프레임에서 FRONT(ID0-3) facing > rear(ID4-7) facing. ID0-3가 항상 카메라 마주보는 면.
- ⚠️ 미적용: v4의 grazing 게이트(front_cos>=0.40, facing_margin>=0.60)는 palletobj에 없음 → top-down 가까운 프레임 5개(000001/004/005/007/008)는 FRONT facing이 0 근처(±0.2)로 0123이 약하게 정해짐(여전히 rear보다는 front). 깔끔히 하려면 게이트 추가 가능(throughput 감소 trade-off).

### 메시 구멍/뾰족 정리 — (a) 원본 유지로 결정
- 진단(MCP bmesh): pallet_full = verts 90778/faces 177723, boundary_edges 3606(구멍 다수), non-manifold 3610, tiny_edges(<1mm) 32. 측면 작은 구멍 多, 심한 스파이크는 적음. 이미 shade_smooth.
- 통풍구 vs 노이즈 구별 = **구멍 경계 둘레**(통풍구=큼>150mm 보존, 노이즈=작음<150mm 채움). 58개 중 작은 40개 대상. top뷰 빨강하이라이트로 통풍구 비침범 확인.
- **A(Fill Holes+Smooth) 한계**: holes_fill이 단순 구멍만 채워 실제 12면만. 측면 표면 요철은 구멍 아니라 fill 무효. 효과 미미.
- **B(Voxel Remesh) 부적합**: 5mm→격자 산산조각, 2mm→더 부서짐. 팔레트가 얇은 격자+두께없는 surface라 voxel remesh가 형태 파괴(boundary 0 되지만 무의미).
- 결정 = **(a) 원본 메시 그대로**. 사유: keypoint(8코너=bbox)는 표면노이즈 무관, 마스크만 약간 거칠 뿐 → 6D pose 학습 영향 작음. remesh로 형태 망치는 것보다 원본이 정확. (근본 개선 원하면 원본 사진 photogrammetry 재처리=C, 미보유 시 보류.)
- 산출(검증용, 사본): `data/pallet/_mesh_proc_compare/`(orig/proc/remesh side·top), `_mask_poc/holdout_mask.png`. 원본 `data/palletobj/pallet_full.obj` 미변경.

## 카메라 구도(elevation) 다양화

### 문제
생성 데이터 카메라가 항상 낮은 측면 구도(elevation 1.9~13°, 평균 6.6°)뿐. 위에서 내려보는 구도 없음.
- 원인: `sample_random_scenario` `h_above=random.uniform(0.15,0.50)`(카메라 높이 0.15~0.5m 고정 범위) + `clock=[3,6,9]`(측면 방위각).

### 수정 (gen_palletobj_scenarios.py 4곳)
- `sample_random_scenario`: `elev_deg = random.uniform(12.0, 60.0)` 추가, return dict에 `elev_deg` 포함.
- `generate_frame`: 카메라 높이를 `elev_deg` 있으면 `h_above = dist_from_center * tan(elev_deg)`로 계산(없으면 SCENARIOS_10용 기존 h_above fallback). elevation 각도가 구도를 결정하므로 dist 무관하게 일정한 올려본 각.
- `meta`: `camera_height_above_floor_m`을 실제 h_above로, `camera_elevation_deg` 추가 기록.

### 검증 (seed 777 재생성)
- elevation 13.5~58.3°(이전 1.9~13°). 000002=15°(측면), 000009=58°(위에서). 위·중간·측면 고루 분포.
- ⚠️ elev 높음(58°) + surf_dist 멈 조합이면 cam_z 7m로 팔레트가 작게 보임(000009). 필요시 elev-dist 조합 제한(높은 elev일 때 dist 축소) 또는 area 게이트 추가 검토.

## json에 COCO 마스크 정보 추가 + purge 크래시 수정 + 만장(v3) 생성

### json 마스크 (COCO RLE) — 사용자 요청
- 기존: annotation에 `visible_mask` png 경로만. → 픽셀 마스크를 json에도 넣음(COCO 호환, segmentation 대비).
- `floor_and_mask.py` `mask_png_to_coco(mask_path)` 신규: 마스크 png 읽어 `bbox_xywh`(COCO) + `area_px` + `rle`(column-major counts, pycocotools frPyObjects 호환 uncompressed RLE) 반환. numpy 벡터 RLE(np.diff/where).
- `gen_palletobj_scenarios.py` render_frame: 마스크 렌더 후 `mask_coco = FM.mask_png_to_coco(mask_path)`, annotation objects[0]에 `mask_bbox_xywh`/`mask_area_px`/`mask_rle` 추가. png 마스크도 그대로 유지(이중).
- 검증(60장): f000000/f000055 모두 json_area == RLE디코드_area == png_area 일치(49391/8160). bbox 정상.
