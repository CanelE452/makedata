## ★ D11A — 원장 연쇄(chained-ledger)로 D1D 를 되살렸다

### 문제

C2C 원장은 `blender_scene` 173파일의 이동 후 위치·SHA256 을 증명한다. cold blend 10개를
그 destination 밖으로 옮기면 C2C verify 가 MISSING 으로 실패한다(Stage 2-D1 에서 실제
발생 → rollback).

### 해결 — `--successor-ledger-chain <json>`

없어진 파일을 통과시키는 유일한 근거는 **파일 단위 SHA256 identity 3중 일치**다:

```
prior ledger 가 기록한 (relative_path, size, sha256)
  == successor ledger 의 source identity (pre_hash)
  == successor destination 의 현재 실측 identity
```

기존 manifest 는 한 바이트도 수정하지 않는다. 16개 조건을 전부 강제한다(prior/successor
manifest SHA256 결속 · prior 원장에 relpath 실재 · size/sha 일치 · successor source ==
prior destination · successor VERIFIED · pre-hash == prior hash · destination 존재/size/
sha · prior 1:1 mapping · successor 가 복수 prior 대표 금지 · path escape · ledger cycle ·
unmapped missing 0 · **prior destination 에 아직 있는 파일은 chain 불가**).

핵심 코드: `manage_pallet_data_layout.py`
`SuccessorChainError` · `load_successor_chain()` · cmd_verify 의 chain 분기.

### ★ 실행 중 발견 — verify 는 멱등이어야 한다

chain 은 successor 원장 SHA256 에 결속되는데, verify 가 재실행마다 `verified_at` 을
갱신해 원장 파일이 바뀌면 **chain 결속이 깨진다.** 실제로 발생:

```
successor chain 오류: successor manifest sha256 불일치
  spec   e2c1a19f29c59470…   actual 500da4140372ecd3…
```

원장은 "언제 **처음** 검증됐는가"를 기록하는 immutable 기록이어야 한다. 첫 검증에만
기록하도록 고쳤다. 멱등 확인: `before=500da414 after1=500da414 after2=500da414`.
테스트 2개로 고정.
